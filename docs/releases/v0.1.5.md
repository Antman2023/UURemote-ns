# v0.1.5 — 关闭后候选处理与可见版本号

- 修复连接失败、断开或关闭后仍继续处理远端候选的问题。libdatachannel 关闭时保留 SDP、释放 ICE 通道，此时迟到的候选会抛出 `Got a remote candidate without ICE transport`，掩盖先前的连接失败。现在清空待用候选并忽略该连接后续的信令；已排队的原始连接状态仍由客户端处理。
- 处理状态检查与应用候选之间发生关闭的并发窗口；活动连接上的解析和状态异常继续正常上报。
- 首页显示 `v0.1.5`。界面版本、启动日志和 NRO 版本统一使用 CMake 项目版本，方便检查实际运行的文件。
- 包含 v0.1.4 的提前候选暂存、ICE / DTLS / SCTP 脱敏诊断和更具体的失败提示，以及大二维码、短信登录和此前的崩溃修复。

五通道 H.264 / Opus 本机回环通过，覆盖连续三轮建立、清理，以及关闭后迟到的候选和 SDP。Switch ARM64 编译、NRO 版本、ZIP CRC 和校验值检查通过。

用户最新复制的日志仍为 `app-start-0.1.3`，没有 v0.1.4 的分层诊断；因此原始真机协商失败原因仍未确定。本版修复的是关闭后的后续异常，不能据此声称串流已恢复。

更新时先退出旧程序，将本版 NRO 覆盖到 **SD 卡根目录下的 `switch/UURemote-ns/UURemote-ns.nro`**，再从 hbmenu 完整应用模式启动。首页必须显示 `v0.1.5`；若仍是旧界面，请检查是否启动了其他目录的旧副本。复测连接后提供 `switch/UURemote-ns/connection.log`，本次启动标记应为 `app-start-0.1.5`。
