# v0.1.4 — ICE 候选顺序修复与协商诊断

- 远端 ICE 候选先于 SDP 到达时先暂存，设置远端描述并准备好本地回答后再应用；支持扁平和嵌套候选格式，断开时清空旧候选。
- `connection.log` 增加 Offer / Answer 收发、候选应用、ICE / 收集 / 信令状态、DTLS 握手与 SCTP 握手阶段，帮助区分网络、加密和数据通道故障。
- 对已知失败只记录固定事件名及数值错误码；不写入原始库日志、地址、SDP、令牌或传输内容。
- ICE 已连接后显示加密与数据通道协商进度；失败提示按已知连接阶段区分。
- 保留大二维码、短信登录和此前的 Horizon 兼容修复。

已通过 Switch ARM64 编译、协议 / 登录 / 后台任务 / 日志脱敏测试，以及禁用线程分离的五通道 H.264 / Opus 本机回环；回环覆盖候选先于 Offer 和 Answer 到达、连续三轮建立与清理。

用户 v0.1.3 的日志显示发送 Offer 约 41 秒后进入错误处理，没有记录崩溃；旧日志不足以判断失败发生在 ICE、DTLS 还是 SCTP。本版补齐排查信息，尚未确认该真机协商失败已解决，继续作为实验性预发布。

下载 ZIP 解压到 SD 卡根目录，覆盖 `switch/UURemote-ns/UURemote-ns.nro`，通过完整应用模式运行。复测一次连接后，请提供 SD 卡上的 `switch/UURemote-ns/connection.log`，确认本次启动标记为 `app-start-0.1.4`。
